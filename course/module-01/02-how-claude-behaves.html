This is the frame for everything after it. Four properties of the model, each treated as a force to design around rather than a defect to fix, the way a structural engineer designs around what steel and concrete actually do. Read it slowly. It is one screen in the official module and it explains why half the later answers are right.

Each property pairs a capability with the limitation that is the same trait seen from the other side, and each has a mitigation an architect reaches for.

Next-token prediction Work built on common patterns: summarising, reformatting, explaining settled ideas Precision on specifics. 2.1Two different errors at the context edge

The module is precise here and the exam can be too. The working-memory edge produces two failures that are easy to conflate.

2.2From property to design consequence

This is the part worth memorising, because it is the reasoning the rest of the certification runs on.

Carry this sentence

A guardrail is not bureaucracy. It is the mitigation for confidence-is-not-validity. A deterministic check in code is the mitigation for non-determinism. When an exam option proposes a control, ask which property it is mitigating. If it mitigates nothing, it is the distractor.

2.3The failure that began with a misread property

The lesson is not that the model is unreliable. It is that a demo is not evidence of determinism, and the four properties are present whether or not your architecture acknowledges them.

A pricing team wants Claude to apply a published discount schedule: orders above a stated volume get a fixed percentage off. The schedule is maintained in a rules table the finance team owns. The engineer proposes prompting Claude with the schedule and letting it compute each discount, to keep the design to one component.

Which property makes this the wrong call, and what is the mitigation?

  1. Knowledge boundary, so retrieve the schedule from a corpus at query time
  2. Working memory, so chunk the schedule and load it progressively
  3. Non-determinism, so the arithmetic belongs in code and Claude calls it
  4. Steerability, so tighten the prompt with explicit worked examples
Non-determinism. The distinguishing question in this family of items is always the same: does this rule have to hold every single time? If yes, code owns it. The model can extract the order volume and invoke the calculation, which uses next-token prediction for what it is good at and leaves the guarantee where guarantees belong.
