The claims triage assistant reaches Decision 4. The users are adjusters, not engineers. Claude reads each claim and drafts the email; the rule engine and the coverage lookup are the insurer's own systems. The insurer runs on AWS under an enterprise agreement, and the CIO's policy is that customer data stays on the approved cloud. Which entry point do you recommend?

Locked in. The section will not tell you whether you were right until the end.

The longest screen in the official module sits here, and the section looks small in the contents list. It is not. Three decisions, made in sequence, and the order is what prevents the most common architecture mistakes.

  1. Which entry point fits the work?
  2. Which build-time interface suits the team?
  3. Which delivery route fits the partner's cloud commitments?

10.2Build-time interfaces

Four layers that stack, not four alternatives
InterfaceWhat it isTradeoff
Direct APIThe HTTP interface. You own retries, streaming, tool use, observability and the UI. The layer everything else sits onMaximum control against maximum responsibility. Use it when an SDK has not exposed a feature you need, or the team prefers raw HTTP
SDKs
Python, TypeScript, Java, Go, Ruby, C#, PHP		The same capability wrapped in language-native types and helpers: auth, request formatting, retries, streaming, tool-use plumbing. The agent loop, if any, is still your codeErgonomics against control. SDK abstractions move at Anthropic's release cadence. The default choice for embedding Claude in a product
MCPAn open protocol for exposing tools, prompts and resources from one server so any MCP-aware client can discover and use them. A sharing convention across products, not a calling convention inside oneReusability across clients against added architectural complexity. If only one client will ever use it, MCP is overhead
Agent SDKThe managed agent loop that powers Claude Code, run from your own application code: iteration, tool execution, termination. TypeScript and PythonManaged loop against custom orchestration. You give up fine-grained control of the loop
Three distinctions the exam can turn on

API and SDK are the same entry point, different ergonomics. The SDK is an opinionated wrapper. The only reason to drop to raw HTTP is a freshly shipped feature the SDK has not wrapped yet.

MCP and API tool use are different layers, not alternatives. An MCP server exposes tools that any MCP-aware client calls using API tool use. Pick MCP when one tool entry point must be reachable from multiple clients; pick raw tool use when the tools live inside one product.

Anthropic SDK and Agent SDK are different products. The first is a convenience wrapper over the API and runs no loop. The second is the managed runtime that does. One request and one response, use the API or SDK. Reusable tools across clients, MCP. Claude acting across multiple turns inside the partner's product, the Agent SDK.

10.3Claude Code: shaping layers and governing layers

Choosing Claude Code starts a second decision: which customisation belongs at which layer. The layers split into two groups, and keeping the split clean is what makes an agent both useful and safe to run.

Shaping what it knows, governing what it may touch
LayerGroupWhen it belongs here
CLAUDE.mdShapingPersistent context for every task in the project: coding standards, repo layout, team conventions
SkillsShapingRepeatable procedures nobody should have to respell: a commit-push-PR flow, a release-notes generator, a schema migration
SubagentsShapingWork that should run read-only, with a restricted tool entry point, or a different system prompt from the main session
MCP serversShapingWhen the same tool entry point must be reusable across clients, for example a team's Linear server that should also work from Claude.ai
HooksGoverningDeterministic gates the agent must not skip, where the guarantee has to come from code rather than prompting
Permission boundaries and approval flowsGoverningAny environment where the cost of an unintended action is non-trivial
Sandboxing and restricted executionGoverningWhere a wrong action has real consequences and approval prompts alone are not a sufficient backstop. The environment enforces the boundary, not the agent's judgment

Six permission modes control what runs without prompting: default asks before each action; acceptEdits approves file edits and common filesystem commands while other Bash still prompts; plan locks the session read-only until a plan is approved; auto classifies actions as safe or risky and is a research preview; dontAsk auto-denies anything that would prompt and runs only what allow rules cover, which makes it the locked-down CI mode; and bypassPermissions skips all checks and is scoped to containers or CI only.

The distinction in one line. Permissions govern what the agent is allowed to touch. Hooks govern what must happen before or after an action.

10.4Delivery routes

Same model on every route. What differs is which cloud account the spend lands in, which identity system authenticates, which region traffic terminates in, and which procurement contract already exists. The decision rule is not technical capability, it is what the partner has already committed to.

10.5Constraints that rule options out first

Some of this is not at your discretion. When a partner is subject to privilege, HIPAA, GDPR, FedRAMP or an internal residency policy, those constraints rule entry points in or out before cost, ergonomics or build effort enter the conversation. Name the governing constraint when you recommend an entry point, and let it eliminate options before preferences do.

10.6Watch out: Claude Code outside engineering

A regional bank proposed an operations assistant for branch staff: look up balances, schedule appointments, answer policy questions. The design was Claude Code on branch laptops with a per-branch CLAUDE.md, MCP servers for the customer database, appointment system and policy corpus, and subagents running compliance checks on every interaction.

Place your bet before the reveal

The module finds three failures in that proposal. Which one does it put first?

Three failures, each visible in the proposal:

  • The entry point was chosen before the user was named. Branch staff do not run terminals. That constraint should have decided the entry point before anything else.
  • MCP was carried forward from a previous project as a default. There were no other Claude clients in the bank, so the reusability that justifies MCP did not apply, and the protocol layer was paying integration cost for nothing.
  • Compliance, the highest-consequence path, was assigned to the weakest deterministic guarantee. The pattern was inverted: the work most needing code-level certainty ran furthest from it.

The architecture that fits: a custom web application calling the API directly, compliance in deterministic server-side code, the UI authenticated through the bank's SSO and shaped like a banking workflow, and tool calls audited at the server boundary.

Same question, after the section

The claims triage assistant: adjusters as users, the insurer's own rule engine and coverage lookup, AWS under an enterprise agreement, customer data on the approved cloud. Which entry point?

A healthcare network wants a clinical documentation assistant that processes patient records. The network already holds a BAA with AWS and has confirmed Bedrock is covered under it. A competing proposal suggests the direct Anthropic API with a separately negotiated BAA.

Which option names both the right choice and the deciding tradeoff?

  1. Bedrock, because the deciding tradeoff is regulatory residency: it pins data to a US region
  2. Bedrock, because the deciding tradeoff is governance: the existing BAA covers this configuration and eliminates the compliance risk first
  3. The direct API with a new BAA, because the deciding tradeoff is control over how PHI flows
  4. Claude.ai Enterprise with a BAA, because the deciding tradeoff is governance: Enterprise adds HIPAA-ready configuration
Bedrock, on governance. These items pair a choice with a reason and score the pair, so a right route with the wrong reason is wrong. The tell is that the scenario states the BAA already covers Bedrock. That is a constraint that has already eliminated options, and it outranks every preference in the room.
