Platform map and primitives

Three layers of the platform, then the seven primitives you build from.

Three words get used as if they were alternatives to each other. They are not. Every deployment involves all three, and collapsing them is the most common source of muddled architecture conversations. Learn the names here; the choosing happens in section 10.

The three layers, in full wording
Three layers, three separate conversations
LayerWhat it isExamplesChosen for
Entry pointWhat a person or system directly interacts with. The wrapper that decides who can talk to Claude and howClaude.ai on web, mobile and desktop; Claude Code; a custom app on the APIThe user and the work
Build-time interfaceHow an engineer programs against Claude. The layer the partner's code is written toThe direct API, the SDKs, MCP, the Agent SDKThe engineering team and the integration
Delivery routeWhere API traffic terminates, and whose infrastructure runs the requestAnthropic directly, AWS Bedrock, GCP Vertex AI, Microsoft FoundryCloud commitments and compliance posture

Three layers, three different stakeholders, and a decision in one rarely dictates the others. A proposal once put Claude Code, an engineering entry point, in front of bank branch staff on the grounds that it is all Claude. It is all Claude, in that the same model sits under every entry point. But the entry point is the wrapper, and the wrapper was built for developers in a terminal. Treating the three layers as one erased the distinction that should have ruled the choice out in the first minute.

A partner says: we will use Bedrock as our entry point, with MCP as the delivery route, because our team already runs on AWS.

What is wrong with that sentence?

  1. Bedrock and MCP cannot be used together in one architecture
  2. Both terms are in the wrong layer, and no entry point has been named
  3. The AWS commitment is not a valid reason to choose a route
  4. MCP is the wrong delivery route for an AWS partner
The layers have been collapsed. Bedrock is a delivery route. MCP is a build-time interface. The entry point, what the loan officer or the analyst actually opens, has not been decided yet, and it is the decision that should come first because it is the one the user feels every day.

3.1Seven primitives, one job each

Before the patterns, the parts. Every architecture later in the module is an assembly of these seven. Being able to name the primitive a scenario needs is a separate skill from naming the pattern, and the module tests it separately.

The seven primitives, in full wording
The seven primitives
PrimitiveJobWhat it is
ToolsActA function the model can call to take an action or fetch a result from your code
MCPConnectA protocol for exposing a set of tools so multiple Claude clients can reach the same entry points
SubagentsIsolate or paralleliseA scoped sub-task handed to a separate context so it runs in isolation or in parallel
HooksGuaranteeDeterministic code fired on defined events to enforce a rule the model cannot skip
SkillsPackage a procedureA versioned, reusable unit of instructions plus optional scripts
Agent TeamsCoordinate peersMultiple agents as coordinated peers, each owning part of a larger goal
Dynamic WorkflowsCompose at runtimeWorkflow steps assembled at runtime rather than fixed in advance
Why this ordering helps. A workflow is primitives wired together in your code. An agent is the model choosing its own sequence of tool calls. A multi-agent system is an orchestrator delegating to subagents. Once the primitives are named, every pattern in section 5 is a combination of things you already recognise.
The vocabulary failure

In one architecture review, someone said we will use an agent. Five people heard five different things: a single tool-using model, a multi-step workflow, a team of subagents, Claude Code, and a chatbot. Twenty minutes went by before anyone noticed they were describing different architectures with the same word.

A team needs two things in the same design. First, a rule that a personally identifiable field is redacted before any prompt leaves their network, with no possibility of the model skipping it. Second, the same set of internal tools reachable from both Claude Code and their own customer-facing app.

Which two primitives do those two jobs?

  1. Hooks, for the redaction guarantee
  2. Skills, for the redaction guarantee
  3. MCP, for the shared tool entry points
  4. Subagents, for the shared tool entry points
Hooks and MCP. Match the primitive to its one-word job: hooks guarantee, MCP connects. If only one client would ever consume those tools, MCP would be paying integration cost for reusability nobody needs, and direct tool use would be the better answer. The second client is what earns it.
