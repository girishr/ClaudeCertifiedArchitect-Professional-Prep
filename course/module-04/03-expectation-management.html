Expectation management

What you may promise about a system that is probabilistic by construction, and what has to be signed before the pilot starts.

Exam domain 6From this kit's domain notes
CCAR-P course / Module 4 / Section 03 of 8

The sponsor asks the question every sponsor asks: "so will it be right?" There is a true answer and an accommodating answer, they are different sentences, and which one you say decides whether the rest of the engagement is a quality conversation or a breach conversation.

This is the conceptual centre of the domain. Everything downstream, the SLA, the pilot gates, the failure conversation, is downstream of whether the expectation was set against a probabilistic system or against deterministic software. Set it wrong here and no later section can recover it.

3.1Never a guarantee, always a target on a named set

Replace the guarantee with three things that travel together, and never send one without the other two.

The substitution
Do not saySay instead
"It will be accurate." "We guarantee 99 percent." "It will not make things up." An accuracy target, measured on a named eval set, with a confidence interval and a stated fallback for when it misses

The named set is what makes the number meaningful and what makes it arguable in a useful way. "94 percent on the 300-case support set as of March, plus or minus 3 points, with anything below the confidence threshold routed to a human" is a claim you can defend, retest and be held to. "99 percent accurate" is a claim nobody can defend, including you.

3.2Good enough is defined against the human baseline

Perfection is the wrong comparator and nobody in the room is currently achieving it. The comparator is the process being replaced.

If humans are 92 percent consistent on the same task, then 90 percent with a review gate and an audit trail is a win, and it is a win you can show. Two sentences follow from that, and both are worth having ready: the baseline has to be measured rather than assumed, and a target set against an unmeasured human baseline is one of the commonest causes of a pilot "failing" while performing perfectly well.

Where this bites later. Section 7 opens with diagnosis before reporting, and a large share of apparent misses turn out to be measurement problems of exactly this kind. The fix for those is upstream, here, in how the target was set.

3.3Explaining non-determinism without the word temperature

An executive does not need the mechanism. They need to know what will be visibly different from the software they are used to, and what you have built to contain it.

The same fact, translated
What they will observeWhat controls it
The same question asked twice can come back worded differently. The substance should be the same; the sentences will not be Pinned model versions, so behaviour does not move under you when a new model ships
Downstream systems need a shape they can rely on, not prose Structured outputs, so the contract with the next system is deterministic even when the language is not
A change to a prompt or a model could silently make something else worse A regression suite, run on every change, which is what turns "we think it is fine" into evidence
Performance can decay over months without anyone touching the code Drift monitoring on the input distribution, because the world changes even when the system does not

No temperature talk with executives. Not because it is too technical, but because it answers a question they did not ask and leaves the one they did ask unanswered.

3.4Acceptance criteria, agreed before the pilot starts

Five elements, in writing, before a single user touches the system.

What an agreed criterion contains
ElementWhy it is in the list
MetricNamed and singular. "Better handling of tickets" is not a metric
DatasetWhich cases the metric is computed over. Without this the metric can be moved by changing the sample
ThresholdThe number that counts as passing, fixed in advance
Measurement methodWho computes it and how. Two people measuring "accuracy" differently is a dispute waiting to happen
SignatoryA named person who agreed all four. This is the element that makes the other four binding

A criterion you cannot fail is not a criterion. Write them as falsifiable statements: given this input class, the system does this, verified against this many historical cases, at this threshold.

Watch out

The single most common scenario in this domain is a pilot running with no agreed criteria and a stakeholder moving the goalposts. The fix is always to pause and agree the criteria, not to argue about the number. Arguing the number is the accommodating move: it engages on the stakeholder's terms, feels collaborative, and cedes the thing actually in dispute, which is who gets to define success and when. You can win that argument three times and still lose the project the fourth time the target moves.

Related and equally tempting: letting the sponsor quietly lower the target. If the target moves, it moves in writing, with the reason, and with everyone who signed the original told that it moved. A target that changed without a record is worse than no target, because it looks like a target to everyone reading the deck later.

3.5Three families of metric, and which one goes in the business case

Keep these apart. Mixing them is how a deck ends up unable to answer the only question the person paying actually has.

Quality, experience, business
FamilyExamplesWho it is for
QualityAccuracy, groundedness, task completionYou and the engineering team. Evidence the thing works
ExperienceLatency, adoption, CSATThe product owner and the users. Evidence the thing gets used
BusinessCost per task, deflection, cycle timeThe sponsor and finance. Only this family belongs in the business case

Groundedness at 0.91 is a real achievement and it is not a business case. Cycle time from 26 hours to 16 is. Both are true at once, which is why the one-artefact rule in section 7 exists.

Leave this section able to answer the sponsor's question in one sentence that contains a number, a named dataset and a fallback. That sentence is the whole of expectation management, and everything the rest of the module does is protect it.
