Workflow or agent?

The most common wrong answer in Domain 1 is an architecture that would work, built one tier more complex than the scenario justifies.

~15 minutes Domain 1, 17% of the exam 5 drills

You already build agentic systems. So this lesson is not about what an agent is. It is about the one judgement the exam keeps testing and that experienced builders keep getting wrong under time pressure: knowing when not to build one.

The win by the end of this page: given a scenario, you name the right tier in under thirty seconds, and you can say out loud which constraint made the decision.

KnowledgeThree tiers, and only one line between them

Anthropic's position in Building effective agents is unusually blunt for a vendor: start with a single augmented LLM call, and add complexity only when simpler solutions demonstrably underperform. Not when it would be more interesting. Not when the client asked for an agent.

Escalate only when forced
TierWho decides the pathYou getYou pay
Augmented LLM Nobody, it is one call Cheapest, fastest, trivially auditable Cannot handle multi-step work
Workflow You, in code, before runtime Predictable cost, latency and audit trail You must know the steps in advance
Agent The model, at runtime Handles genuinely unpredictable work Variable cost and latency, harder to debug and audit
The whole lesson in one sentence

The workflow/agent line is predictability of the path, not difficulty of the task. A hard task with a fixed sequence is still a workflow.

That distinction does the heavy lifting because exam scenarios are written to make hard tasks feel like they need agents. A 40,000-claim insurance backlog sounds like it needs autonomy. If 85% of those claims follow one of three known paths, it needs a router and three prompt chains, and the agent answer is the trap.

Why this bites experienced people. If you build agents daily, agentic solutions are cheap for you to imagine and therefore feel proportionate. The exam is scored by someone asking whether a mid-sized client should pay for variable latency and a harder audit story. Read every scenario as if you are defending the design to a CFO.

The escalation test

Run these in order. Stop at the first "no".

  1. Does a single augmented call pass eval? If yes, ship it. You are done.
  2. Do you know the steps before runtime? If yes, it is a workflow. Pick the pattern that fits the shape.
  3. Can the path be hardcoded at all? If no, and the model must act on environment feedback in a loop, now you have an agent.

Then one veto, applied last: if failures are costly and irreversible and you cannot sandbox or checkpoint, do not hand the path to the model regardless of how unpredictable it is. Unpredictability argues for an agent. Irreversibility argues louder against one.

SkillFive scenarios, thirty seconds each

Read the last sentence first, find the binding constraint, then answer. Feedback is immediate, and the reason matters more than the score.

A national insurer has 40,000 first-notice-of-loss submissions backed up. Roughly 60% are auto glass claims that follow one fixed path, 25% are property claims needing a different fixed set of checks, and 15% are liability claims that always go to a human adjuster. There is a hard 8 second SLA on the customer acknowledgement.

Which architecture gives the best accuracy per dollar for the automatable share?

  1. Classify the submission, then route it to a fixed per-category prompt pipeline.
  2. Give one agent every claim-handling tool and let it choose the sequence.
  3. Run all three category pipelines and select the highest reported confidence score.
  4. Chain five refinement passes so the final answer reaches its maximum accuracy.
The binding constraint was the 8 second SLA, and the giveaway was that the categories were enumerated for you. When a scenario tells you the categories, it is telling you classification is tractable. Routing plus fixed chains is the cheapest thing that clears the bar.

A platform team wants Claude to apply a cross-cutting API change across a monorepo. Which files need touching is not known until the codebase is inspected, and it differs on every run. There is no latency pressure, the job runs nightly, and every change lands in a reviewable pull request.

Which pattern fits?

  1. Split the work in code and run each file edit concurrently.
  2. Let a lead model decompose at runtime and delegate to workers.
  3. Chain a fixed sequence of passes over the whole repository once.
  4. Route each request to one specialised prompt chosen by a classifier.
Note what made this safe as well as correct: no latency pressure and a pull request gate. Unpredictable decomposition argues for the orchestrator, and the reviewable PR removes the irreversibility veto.

A compliance team reviews each vendor contract on four fixed axes: data residency, liability cap, termination rights and subprocessor disclosure. Every contract gets all four. The reviews do not depend on each other, and the team wants the turnaround as fast as possible.

Which pattern fits?

  1. Orchestrator-workers, so the planner can decide the split at runtime.
  2. Sectioning, because the four subtasks are already known before runtime.
  3. Evaluator-optimizer, so each draft is critiqued before it is accepted.
  4. Voting, because running each subtask twice raises confidence in results.
This is the favourite trap in Domain 1. Sectioning and orchestrator-workers both fan out, so they look interchangeable. Sectioning: you decide the split, in code. Orchestrator-workers: the model decides it, at runtime. If the scenario lists the subtasks, the orchestrator is overbuilt.

You are deciding whether to escalate from a workflow to an autonomous agent.

Which signals genuinely justify the escalation?

  1. The number of steps varies unpredictably with each input.
  2. The task is difficult and requires careful multi-step reasoning.
  3. The model must react to feedback from its environment.
  4. The stakeholder asked specifically for an agentic AI solution.
  5. The output quality improves when you add more context.
Both correct answers describe the path being undecidable in advance. Everything else describes a task being hard, a person being opinionated, or context being short, and none of those move you up a tier. Option D is worth sitting with: the exam grades the consulting half too, and the right response there is to re-run discovery, not to build what was named.

A procurement agent researches suppliers, appends findings to an internal notes record, drafts an outreach email and sends it. The team wants the efficiency case to survive: a human gate on every step would erase the savings that justified the project.

Where does the human checkpoint go?

  1. Before every tool call the agent makes, without any exceptions.
  2. Before the outbound email send, which cannot be undone afterwards.
  3. After the run completes, when a reviewer samples the transcripts.
  4. Before the internal note update, which touches the shared record.
The rule to carry: checkpoints go at irreversible or high blast-radius actions. Money movement, production writes, external communications, permanent deletions. Everywhere else, log and sample. When two governance options both look defensible, pick the one that preserves the ability to undo.
