Metrics and agent evaluation

Choosing the one metric the system is judged on, and why an agent is graded on where it ended up rather than how it got there.

Exam domain 4From this kit's domain notes
CCAR-P course / Module 2 / Section 09 of 12

Questions in this area hand you a system and ask for the primary metric, or for two metrics. The mistake is picking the metric that is easiest to collect rather than the one that moves when the thing you care about breaks. Tokens per second is easy to collect and tells a chat user nothing.

9.1Eight metrics and when each is primary

The metric table. The right column is the examinable part
MetricDefinitionPrimary when
Accuracy / task fidelityCorrect outputs over totalClassification, extraction, deterministic answers
Task completion rateGoal achieved end to end without human rescueAgents doing multi-step work
TTFTTime to first tokenStreaming, chat, anything a human is watching
Total latencyPrompt to final tokenSynchronous batch-ish jobs, API contracts
ThroughputRequests or tokens per unit timeBulk pipelines, capacity planning
Cost per taskAll model calls in one task, not per requestAgents, where one task is many calls
Safety and securityRefusal correctness, injection resistance, PII leakage, unsafe tool-call rateAnything with write-capable tools or user-generated input
Business KPIDeflection, time saved, conversion, resolution rateThe thing your sponsor funds

Two of these carry a trap each. Cost per task is the right unit for agents because per-token cost can fall while task cost rises, when the agent simply takes more turns. And agent latency is dominated by the number of sequential tool calls, not by tokens per second, so a faster model may not move it at all.

Define success criteria as SMAR: specific, measurable, achievable, relevant. Expect them to be multidimensional rather than one number, which is also why the multiple-response items in this domain ask for two metrics rather than one.

Watch out

"Measure tokens per second" as the user-facing latency metric for chat is wrong. TTFT is what the user feels. Streaming improves TTFT only and does nothing to total latency, so "enable streaming" is not an answer to a total-latency constraint either.

9.2Agents are graded on the end state

Two evaluation modes, and which one is primary
ModeWhat it asksStatus
Final-outcome, or end-stateDid the database end up right. Was the ticket created with the right fieldsPrimary signal. Robust to alternative valid paths
TrajectoryWas the sequence of calls correct, efficient and safeDiagnostic by default. Primary only when the path itself matters: compliance, irreversible actions, cost control

The corresponding trap is grading against a single golden trajectory when many paths are valid. It is over-strict, it fails correct runs, and it quietly trains you to make the agent imitate one route rather than achieve the goal.

Tool-call correctness decomposes into five checks, and a question may ask for the list: the right tool, the right arguments, the right order, correct handling of a returned error, and no unnecessary calls.

9.3Instrument beyond accuracy

The extra series are not decoration. Each one points at a specific defect.

What to record, and what it tells you
SeriesReads as
Per-call runtime and total task durationWhere the sequential tool calls are going
Number of tool calls per taskConsolidation debt. Tasks completing in twelve calls that should take three
Total tokensContext pressure, and the input to cost per task
Error rate by error typeRepeated near-duplicate calls point at pagination defaults. Invalid-parameter errors point at descriptions
The diagnostic move. Splitting error rate by type is what turns "the agent is flaky" into "the page size is 10 and the model keeps paging". Aggregate error rate cannot tell you that.

9.4Multi-turn evaluation

Single-turn evals miss the failures conversational systems actually have: state that does not carry over, corrections that are ignored ("no, the other account"), context that is dropped mid-conversation. Use scripted user simulators and grade the conversation, not isolated turns.

The short form for the exam: one metric for an agent is task completion rate, guarded by cost per task and unsafe-action rate. If the scenario says the path is regulated or the actions are irreversible, trajectory moves from diagnostic to primary.
