Observability across multi-step systems

Tracing an agent run well enough to debug it, without exporting anything the data agreement does not cover.

Exam domain 3From this kit's domain notes
CCAR-P course / Module 2 / Section 07 of 12

A single call either worked or it did not. A twelve-step agent run fails in the middle, and the only question that matters is which step, with what arguments, holding what context. So the unit of observability is not the request. It is the trace: one span per agent turn, child spans per model request and per tool call.

The Claude Agent SDK emits exactly that shape, which is worth knowing because a scenario may name the spans.

The span structure the Agent SDK emits
SpanCovers
claude_code.interactionOne turn
claude_code.llm_requestOne model request: model, latency, token counts
claude_code.toolOne tool call, with children claude_code.tool.blocked_on_user and claude_code.tool.execution
claude_code.hookHook execution

Subagent spans nest under the parent's tool span, so a delegation chain reads as one trace rather than three disconnected ones. W3C trace context propagates automatically, so the agent run also nests inside your application's own trace.

7.2Telemetry is structural by default, and that is the answer

What you get without asking: durations, model names, tool names, token counts. Prompt and tool content is opt-in, through OTEL_LOG_USER_PROMPTS, OTEL_LOG_TOOL_DETAILS, OTEL_LOG_TOOL_CONTENT and OTEL_LOG_RAW_API_BODIES. Leave them off unless the pipeline is cleared for that data.

This is the answer to any scenario phrased as "we need traces without exporting customer PII". You do not need a redaction layer or a separate collector. The default already excludes content, and the named mistake is turning an opt-in on for convenience.

Watch out

"Enable OTEL_LOG_RAW_API_BODIES for better debugging" is a real setting and a wrong answer unless the scenario has told you the pipeline is approved for full conversation content. Read the data-handling sentence in the scenario as a constraint, not as background.

7.3Attribution, and the operational traps

What to attach, and what breaks if you do not
ConcernWhat to do
Cost and token attributionStitch calls together with session.id
Per-tenant cost and per-user auditAdd enduser.id and tenant.id as resource attributes, then feed tool_decision, tool_result, mcp_server_connection and permission_mode_changed events into a SIEM
Short-lived processes losing telemetryBatched exports are dropped when the process exits. Lower OTEL_*_EXPORT_INTERVAL. Defaults are 60s for metrics, 5s for traces and logs
The console exporterNever use it under the SDK. It collides with the message channel
Replay and debuggingKeep raw transcripts of tool calls and results, not just final answers
Why raw transcripts. Anthropic's own tool-improvement loop reads them, and what the agent omits from its own feedback is often more informative than what it says. A summary has already thrown away the evidence.

7.5Common distractors, Domain 3

Eleven wrong answers and the one word that kills each
The optionWhy it is wrong
"Use MCP sampling so the server stays model-agnostic"Deprecated in 2026-07-28
"Register the client dynamically (RFC 7591)"Deprecated in favour of Client ID Metadata Documents
"Validate the token's signature"Necessary but insufficient. The named requirement is audience validation
"Add PKCE to prevent mix-up attacks"PKCE protects the code, not the authorization server's identity. Issuer validation is the stated mitigation
"Expose all endpoints as tools for full capability"Directly contradicted. Consolidate around workflows
"Increase top-K to fix retrieval"Wrong when the failure is lexical or the chunks are context-poor
"Chunk smaller to improve recall"Smaller chunks lose the context that makes them retrievable. Add chunk-level context instead
"Set idempotentHint: true to make retries safe"Annotations are untrusted hints, not behaviour
"Enable OTEL_LOG_RAW_API_BODIES for better debugging"Only when the pipeline is approved for full conversation content
"Sandbox the code, so the script's calls are pre-approved"The broker must still evaluate each call
"Cache the deferred tool definitions"defer_loading plus cache_control on one tool is a 400

Domain 3 is done. The pattern across all of it: the constraint in the scenario picks the mechanism, and the security answer is always the one that narrows what a single compromised component can reach.
