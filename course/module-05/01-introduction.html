Running it without you

Everything in this domain is one question: does the thing you left behind enforce the behaviour, or only suggest it?

Exam domain 7From this kit's domain notes

The system works. The evals pass, the pilot is signed off, the security reviewer is satisfied. Then you roll off, and eight engineers who did not design it have to run it, extend it, and keep it inside the boundaries you drew. What holds those boundaries in place is a set of files in a repository and a policy file on the fleet.

So the domain is not about tooling. It is about which of those files is a guarantee and which is a suggestion. CLAUDE.md is context: it shapes behaviour without ensuring it. Hooks and permission rules are enforcement: they run whatever the model decided. Roughly half the wrong answers here are "put it in CLAUDE.md" for something that has to happen every single time, or "write a hook" for something that was only ever guidance.

This is the module not to overinvest in

Domain 7 is 7 percent of the paper, the smallest of the seven, which is about four questions out of 63. The official module is 45 minutes, the shortest in the path. The material is not hard and it is not deep: it is four ordered lists you either recall or do not, plus the enforce-versus-suggest distinction above. Cover it once, drill the lists until they come out in order, and move on. If you find yourself on a third pass here while Module 2 is still shaky, you are optimising the wrong 7 percent.

1.1The two shapes a Domain 7 question takes

Precedence. Two pieces of configuration disagree and the item asks which one applies. There are four ordered lists in this domain and they are all worth knowing cold: settings, the CLAUDE.md scopes, subagent definitions, and MCP servers. The settings list is the one with a counter-intuitive step in it, so that is the one to expect.

Mechanism fit. The stem gives you a requirement, usually in the words a security reviewer or a tech lead would use, and the options are all real mechanisms. The requirement's wording tells you the answer. "Must happen on every write, regardless of what Claude decides" is a hook. "Nobody in the org may turn this off" is managed settings. "Engineers should follow this convention" is CLAUDE.md or a path-scoped rule. Read the stem for the strength of the obligation before you read the options.

The test that resolves most of them. Ask whether the requirement survives an engineer who ignores it and a model that happens to choose otherwise. If it has to, it belongs in code or in policy, not in prose.
